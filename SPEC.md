# Archive — build spec

A personal capture-and-publish archive. Fragments are captured by phone all week;
posts are assembled from fragments in a weekly session; posts belong to journeys;
journeys belong to identities.

This document is the contract. Build in the order given. Do not add features that
are not listed here.

---

## 0. Guiding constraint

Every decision is judged against one question:

> Is this helping the author document, or is the author now maintaining a
> documentation system?

When in doubt, build less. The archive is the product; the site is a reader for it.

---

## 1. Architecture

```
Android phone
   │  (photo + caption, or text)
   ▼
Telegram bot  ──── transport only, nothing is stored here long-term
   │
   │  GitHub Actions cron, every 15 min
   ▼
┌──────────────────────────────┬──────────────────────────────┐
│ GitHub repo (public)         │ Cloudflare R2 (bucket)       │
│  markdown, frontmatter, all  │  images, resized on ingest   │
│  text, all structure         │                              │
└──────────────────────────────┴──────────────────────────────┘
   │                                        │
   │  static site build                     │
   ▼                                        │
GitHub Pages  ◄─────── <img src> ───────────┘
```

Text in Git, media in R2, site on Pages. Never put images in Git.

## 3. Content schemas

All content files are markdown with YAML frontmatter. Frontmatter is the data
model; the body is prose.

### 3.1 Fragment

Written only by `ingest.py`. Never hand-edited except to set `journey`.

```yaml
---
id: 2026-08-18-142307
captured_at: 2026-08-18T14:23:07+05:30
type: photo              # photo | text | video | audio
media:                   # R2 object keys, omit for text fragments
  - f/2026-08-18/142307-1.webp
  - f/2026-08-18/142307-2.webp
journey: null            # slug, or null
spark: false             # true if caption contained "!"
consumed_by: null        # post slug once used, or null
source: telegram
---

Third attempt at the ochre ground. Too warm.
```

Rules:
- `journey` defaults to `null`. Capture requires zero decisions.
- A hashtag in the caption that matches `config/journeys.yml` sets `journey` and
  is stripped from the body. An unmatched hashtag stays in the body verbatim.
- A `!` anywhere in the caption sets `spark: true` and is stripped.
- Fragments are never deleted. Unused fragments are meaningful data.

### 3.2 Post

Hand-written (or generated by the assembly step, later). The published unit.

```yaml
---
slug: 2026-08-23-ochre-ground
title: The ochre problem
published: 2026-08-23
journey: painting-myths        # exactly one, or null
fragments:                     # ordered; controls render order
  - 2026-08-18-142307
  - 2026-08-19-101122
---

Body prose. Fragments are rendered inline in the order listed above,
interleaved with this text at `{{fragment:ID}}` markers if present,
otherwise appended in order after the prose.
```

### 3.3 Journey

```yaml
---
slug: heros-journey-structure
title: Hero's journey structure
identity: mythic-artist
status: abandoned              # active | paused | abandoned | completed
started: 2026-02-11
ended: 2026-04-03              # required if abandoned or completed
emerged_from: painting-myths   # slug or null
reason: Too tidy. Nothing in my life resolves like that.
---

Opening note: what made me curious about this. Written on day one,
never edited.
```

Rules:
- `reason` is REQUIRED when status is `abandoned`. Build fails without it.
- `emerged_from` is the only relationship field. Journey genealogy is derived
  from it — do not build a separate graph structure.
- A journey's `identity` may change over time. That is expected.

### 3.4 Identity

The five identities, fixed for v1:

```
painting               # painting, calligraphy, mark-making
film                   # filmmaking, cinema, monologues
sound                  # music, sound design
advertising            # visual communication, commercial work
making-stencil-frame   # the product, as an activity
```


```yaml
---
slug: mythic-artist
title: Mythic artist
order: 2
---

One paragraph. What this territory is, at the moment of writing.
```

## 4. Ingest job

`scripts/ingest.py`, run by `.github/workflows/ingest.yml` on a 15-minute cron
and on `workflow_dispatch`.

Steps:

1. Read offset from `.state/telegram-offset.json`.
2. `getUpdates` with that offset.
3. Group messages: same `media_group_id`, OR same sender within a 120-second
   window, become ONE fragment with a media array.
4. For each media item: `getFile`, download, resize to max 1600px on the long
   edge, convert to WebP q80, upload to R2 under `f/YYYY-MM-DD/HHMMSS-N.webp`.
5. Handle both `photo` (compressed) and `document` (original) message types.
6. Extract EXIF `DateTimeOriginal` if present; otherwise use the Telegram
   message date. Store as `captured_at` in Asia/Kolkata.
7. Parse caption for hashtags and `!`.
8. Write the fragment markdown file.
9. Write the new offset.
10. Commit everything as a SINGLE squashed commit: `ingest: N fragments`.
11. If no new messages, exit without committing.

`ingest.py` writes a `dimensions: [width, height]` field on each media entry,
read from the image at resize time. `image-dimensions.ts` uses it when present
and only falls back to fetching when absent.

Failure handling: on any exception, open a GitHub issue titled
`ingest failed <date>` and exit non-zero. Silent failure is the one unacceptable
outcome — `getUpdates` discards messages older than 24h, so a quiet break loses
data permanently.

Logging: never print token values, R2 keys, or full URLs containing credentials.
The repo is public and Actions logs are world-readable.

### Secrets required

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_ID`, `R2_ACCESS_KEY`,
`R2_SECRET_KEY`, `R2_ENDPOINT`, `R2_BUCKET`, `R2_PUBLIC_BASE`.

Reject any message whose sender id is not `TELEGRAM_ALLOWED_USER_ID`. The bot is
discoverable; the archive is not a public inbox.

## 5. Media verification

`scripts/verify_media.py`, run monthly on cron.

Walk every fragment, collect every `media` key, HEAD each against R2. Any missing
object opens an issue listing the broken fragment ids. Dead references are how
split archives rot quietly.

## 6. Site

Static site generator: **Astro**. Reasons: reads markdown + frontmatter natively
with typed content collections, ships zero JS by default, builds fast, and the
output is plain HTML that will still work in ten years. No client-side framework.
No React. No Tailwind unless it saves real time.

### Routes

| Route | Content |
|---|---|
| `/` | Feed. Published posts, newest first. |
| `/posts/[slug]` | Single post. |
| `/identities` | Index of identities. |
| `/identities/[slug]` | Identity page: journeys grouped by status. |
| `/journeys/[slug]` | Journey page. Opener, then posts OLDEST FIRST. |
| `/now` | Dated "where I'm at" notes, newest first, older ones kept below. |

Journey pages are chronological forward. This is deliberate: a journey read
oldest-first is a story; newest-first it is a blog.

Fragments have no route of their own in v1. They are only visible inside posts.

### Comments

Giscus, backed by GitHub Discussions on this repo. No database, no third-party
service, no tracking. Comments stay in Git alongside the archive.

Comments appear on POST pages only. Not on fragments, not on journeys, not on
identities. A journey page reads as uninterrupted thinking.

Setup: enable Discussions on the repo, create a `comments` category, install the
giscus app, and embed the script on the post template with `mapping="pathname"`.

### Not in v1

Search. Tags. Post-to-post links. Multi-journey posts. RSS is optional and cheap —
add it if trivial. No graph visualisation of any kind.

## 7. Visual language

The site should read as a field notebook, not a product.

**Ground.** Warm off-white page (approx `#f4f0e6`), ink near-black (approx
`#1a1a18`). Content sits directly on the ground. No cards, no drop shadows, no
rounded containers. Rules and dividers are 1px ink lines.

**Type — four faces, all Google Fonts, all sans or mono. No serif.**

| Role | Face | Usage |
|---|---|---|
| Structure | Archivo 500 | Labels, nav, status. Uppercase, letterspaced ~0.1em. |
| Body | Instrument Sans | Post and journey prose, 17–18px, generous line-height. |
| Metadata | Space Mono | Timestamps, ids, counts. Small. |
| Annotation | Caveat | Margin notes, abandonment reasons only. |

Caveat is capped at two lines anywhere it appears. Handwriting used for paragraphs
looks like a greeting card; used for three words in a margin it looks like a person.

Do NOT substitute Inter, Poppins, Montserrat, DM Sans, or Lato. Those read as
generated-template defaults and undercut the whole premise.

**Rotation.** Every image gets a deterministic tilt between −2.5° and +2.5°,
derived by hashing the fragment id so it never changes between builds. This single
detail carries most of the scrapbook feel. Do not randomise at runtime.

**Status marks.**
- Active — no mark, full-weight title.
- Paused — title wrapped in square brackets.
- Completed — small hand-drawn tick box after the title.
- Abandoned — a hand-drawn SVG strike-through across the title with a slight
  wobble (a bezier, not a straight line), the `reason` beneath it in handwriting,
  and an `↳ became: <journey>` line if another journey has this one as
  `emerged_from`. Struck through, still legible. Never faded, never hidden.

**Metadata is stamped.** Timestamps visible everywhere, in mono, small. Fragment
counts shown as numbers. The evidence of when things happened is the point.

**No motion.** No scroll animation, no fade-in, no hover transitions beyond a
plain underline. Static paper. The liveliness comes from the content being messy,
not from the interface moving.

**Field notes, not skeuomorphism.** This distinction is the most important rule in
this section.

Skeuomorphic means *depicting* paper: torn edges, coffee stains, ruled-notebook
background images, faux tape, paper textures, drop shadows imitating lifted corners.
All of it is banned. It is costume, and it reads as fake on sight.

Field notes means *behaving* like paper: things are not perfectly aligned, entries
are dated obsessively, corrections stay visible, and layout follows what got
recorded rather than a grid. Flat colour, real type, honest structure.

Hard prohibitions: no raster textures, no paper or canvas background images, no
faux-tape graphics, no torn-edge SVGs, no drop shadows, no simulated staples,
pins, or paperclips.

The materiality comes from three things only — typography, imperfect alignment,
and visible timestamps.

**Avoid.** Generic SaaS UI, rounded cards, gradients, sterile dashboards, stock
iconography, anything that reads as a personal-brand template.

## 8. Build order

Do not skip ahead. Each step must work before the next begins.

1. Repo skeleton, schemas, three or four hand-written sample fragments, one
   sample post, two journeys (one abandoned), one identity.
2. Astro site reading those files. Feed + post page only. Unstyled.
3. Journey page and identity page. Status marks including the strike-through.
4. Visual language pass: type, ground, rotation, stamped metadata.
5. R2 upload path and public URLs, verified with a real image.
6. `ingest.py` + workflow. Real capture begins here.
7. `verify_media.py` + monthly cron.
8. `/now` page.
9. Giscus on post pages.

Steps 1–4 are testable with hand-written files and no infrastructure at all. That
is deliberate: the reader should exist before the pipe is built, so the pipe has
somewhere to deliver to.

---

## 9. Explicitly later

Weekly assembly UI. Session clustering by time gap. Spark/trigger analysis.
Journey map visualisation. Audio transcription. Video. Full-text search.

The data model above already supports every one of these. None of them get built
until the archive has months of real content in it, because designing them now
means designing against imagined data.
